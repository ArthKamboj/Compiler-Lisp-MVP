# Micro-Lisp Compiler & Virtual Machine

A lightweight, stack-based Lisp compiler and virtual machine written from scratch in modern C++17.

This project demonstrates the complete lifecycle of a programming language front-end and back-end: taking raw string input, building a type-safe Abstract Syntax Tree (AST), compiling it down to linear bytecode, and executing it on a custom stack-based virtual machine. 

With the addition of control flow and Call Frames, this Micro-Lisp engine is Turing-complete and supports persistent runtime state, allowing for complex multi-line evaluation.

## Features Supported
* **Primitives:** Numbers, Booleans (`#t`, `#f`), Symbols
* **Math Operations:** `+`, `-`, `*`, `/`
* **Variable Binding:** `(define x 10)`
* **Boolean Logic & Comparisons:** `=`, `<`, `>`, `<=`, `>=`, `!=`
* **Control Flow:** `(if condition true-branch false-branch)`
* **User-Defined Functions (Closures):** `(lambda (x) (* x x))`

## Architecture

The project is broken down into five distinct phases of execution, ensuring a clean separation of concerns between syntax parsing, memory state, translation, and execution.

### 1. The Lexer (`lexer.h`, `lexer.cpp`)
The lexer (or scanner) is the first stage of the pipeline. It takes a raw string of Lisp code and breaks it into an array of distinct, manageable text tokens. It does this by padding structural characters like parentheses with whitespace, allowing standard string-stream parsing to extract keywords, symbols, and primitive values.

### 2. The Parser and AST (`parser.h`, `parser.cpp`, `types.h`)
The parser consumes the tokens generated by the lexer and builds a hierarchical Abstract Syntax Tree (AST).

- **`types.h`** defines the `LispVal` struct, which uses modern C++17 `std::variant` to act as a memory-safe recursive union. A `LispVal` can hold a `double`, `bool`, `std::string` (symbol), a `std::vector` of `LispVal`s (a list), or a compiled `LispFunction`.
- **`parser.cpp`** implements a recursive descent parser. It reads tokens from left to right, dynamically building nested `LispVal` nodes whenever it encounters an open parenthesis.

### 3. The Environment (`environment.h`)
The environment is the memory structure responsible for variable binding and lexical scoping. It is implemented as a class wrapping a `std::unordered_map` that maps string symbols to `LispVal`s.

Each environment holds a `std::shared_ptr` to an outer (parent) environment. If the VM attempts to fetch a variable that does not exist in the local scope, the environment recursively searches up the parent chain until it finds the global scope. This architecture natively supports Closures for local function parameters.

### 4. The Bytecode Compiler (`compiler.h`, `compiler.cpp`)
The compiler bridges the front end (AST) and the back end (VM). It recursively traverses the AST and flattens it into a 1D array of machine instructions (bytecode).

- **Postfix Translation:** Translates math and logic operations into stack-based Reverse Polish Notation (`PUSH`, `PUSH`, `ADD`, `EQ`).
- **Control Flow:** Uses **backpatching** to implement `if` statements, emitting `JUMP` and `JUMP_IF_FALSE` instructions with calculated offset distances.
- **Functions:** Packages `lambda` bodies into isolated bytecode blocks and emits them as callable `LispFunction` objects.
- **Persistent State:** Acts as a "Master Compiler," appending new instructions to a continuous global bytecode array across sequential REPL inputs.

### 5. The Virtual Machine (`vm.h`, `vm.cpp`)
The Virtual Machine (VM) is the execution engine. It maintains a runtime stack (`std::vector<LispVal>`), a reference to the active `Environment`, and a **Call Stack** (`std::vector<CallFrame>`).

It loops through the compiler-generated bytecode utilizing an instruction pointer (`ip`):

- **Data & Math:** Executes standard stack operations (`CONST`, `ADD`, `LESS_THAN`, etc.).
- **Branching (`JUMP`, `JUMP_IF_FALSE`)**: Modifies the instruction pointer to skip over specific blocks of bytecode for `if/else` logic.
- **Call Frames (`CALL`, `RETURN`)**: When a function is called, the VM saves its current instruction pointer and environment to the Call Stack, spins up a temporary local scope for parameters, and jumps into the function's bytecode. Upon `RETURN`, it pops the bookmark and seamlessly resumes execution.

## Build Instructions

This project requires a C++ compiler with C++17 support, such as GCC 7+, Clang 5+, or MSVC 19.14+.

To compile the project from the terminal, link all `.cpp` files together:
```bash
g++ -std=c++17 main.cpp lexer.cpp parser.cpp compiler.cpp vm.cpp -o lisp_compiler
```

## Usage



Run the compiled executable:



- **Linux/macOS:** `./lisp_compiler`

- **Windows:** `lisp_compiler.exe`



## Example Execution



The `main.cpp` file contains a test pipeline that sequentially executes Lisp commands, persisting the state of the variables across evaluations.



### Lisp

```lisp

(define age 20)
(if (>= age 18) 100 200)

(define square (lambda (x) (* x x)))
(+ (square 3) (square 4))

```
